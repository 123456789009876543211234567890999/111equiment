# 設備掃描借用／歸還系統

以手機掃描 QR Code 借用與歸還設備，狀態與紀錄即時寫入 Google Sheet，並提供一個狀態總覽網頁。使用前須以試算表中的帳號密碼登入，每筆借還紀錄都會記下操作人。

---

## 1. 系統架構

```
                                ┌──────────────┐  action=login
                 未登入時轉入 ─▶ │ login.html   │ ────────────┐
                                │ 登入頁        │             │
                                └──────────────┘             ▼
┌──────────────┐  掃描 QR Code   ┌──────────────┐  HTTP POST   ┌──────────────────┐
│ 手機瀏覽器    │ ─────────────▶ │ index.html   │ ────────────▶ │ Google Apps      │
│ (GitHub Pages)│                │ 掃描借還頁    │ borrow/return│ Script (Code.gs) │
└──────────────┘                └──────────────┘   + token     └────────┬─────────┘
                                                                        │ 讀寫
┌──────────────┐  每 10 秒輪詢  ┌──────────────┐  HTTP POST             ▼
│ 手機／電腦    │ ─────────────▶ │ status.html  │ ────────────▶ ┌──────────────────┐
│ 瀏覽器        │                │ 狀態總覽頁    │  list / log  │ Google Sheet     │
└──────────────┘                └──────────────┘   + token     │ Equipment_List   │
                                                               │ 使用者名單        │
                                                               │ 借還紀錄          │
                                                               └──────────────────┘
```

| 層級 | 技術 | 部署位置 |
|---|---|---|
| 前台 | HTML + JavaScript + html5-qrcode | GitHub Pages |
| 後台 | Google Apps Script（網頁應用程式） | Google 雲端 |
| 資料庫 | Google Sheet | Google 雲端 |
| QR Code | quickchart.io 免費 API，由 Sheet 公式產生 | Google Sheet 儲存格 |

---

## 2. 檔案說明

| 檔案 | 用途 |
|---|---|
| `login.html` | 登入頁。輸入使用者編號與密碼，成功後進入掃描頁或總覽頁。 |
| `index.html` | 掃描頁。選擇借用或歸還模式，掃 QR Code 後呼叫後台更新狀態。須先登入。 |
| `status.html` | 總覽頁。顯示所有設備狀態、統計數字與最近借還紀錄，自動更新。須先登入。 |
| `auth.js` | 三個頁面共用的模組：後台網址 `API_URL`、登入狀態、API 呼叫、登出。 |
| `Code.gs` | 後台。驗證登入、接收前台請求，讀寫 Google Sheet。 |
| `README.md` | 本文件。 |

## 3. Google Sheet 結構

### 3.1 `Equipment_List` 分頁（設備，需手動建立）

第一列為標題列，程式從第二列開始讀取。

| 欄 | 欄名 | 說明 |
|---|---|---|
| A | 設備編號 | 唯一值，建議 4 碼數字，例如 `1001`。QR Code 內容即為此值。 |
| B | 名稱 | 例如 `數位相機` |
| C | 狀態 | 只能是 `可借用` 或 `借出中`，由程式自動更新 |
| D | QR Code | 公式產生，見 3.4。程式不讀取 |
| E | 廠牌 | 例如 `Canon` |

### 3.2 `使用者名單` 分頁（使用者，需手動建立）

第一列為標題列，程式從第二列開始讀取。

| 欄 | 欄名 | 說明 |
|---|---|---|
| A | 使用者編號 | 登入帳號，唯一值，例如 `1001` |
| B | 姓名 | 登入後顯示在畫面上，並寫入借還紀錄 |
| C | 職稱 | 例如 `teacher`，登入後顯示在姓名旁 |
| D | 狀態 | 空白代表啟用。填 `不啟用` 或 `停用` 時該帳號無法登入 |
| E | 密碼 | 登入密碼。空白的帳號無法登入 |

新增使用者只要往下加一列，不需要重新部署。把狀態改成 `不啟用` 後，該使用者已登入的裝置在下一次操作時也會被登出。

密碼若以 `0` 開頭（例如 `0000`），請先把 E 欄的格式設為「純文字」再輸入，否則試算表會把它存成數字 `0`。

### 3.3 `借還紀錄` 分頁（程式自動建立）

第一次借用或歸還成功時自動建立，不需手動新增。

| 欄 | 欄名 | 說明 |
|---|---|---|
| A | 時間 | 格式 `yyyy/MM/dd HH:mm:ss` |
| B | 設備編號 | |
| C | 名稱 | |
| D | 廠牌 | |
| E | 動作 | `借用` 或 `歸還` |
| F | 更新後狀態 | `借出中` 或 `可借用` |
| G | 使用者編號 | 操作人的編號 |
| H | 使用者 | 操作人的姓名 |

加入登入功能前建立的紀錄分頁只有 A 到 F 欄。下一次借還時程式會自動補上 G、H 的標題，舊紀錄的這兩欄留空。

### 3.4 QR Code 產生公式

在 `Equipment_List` 的 D2 輸入後往下填滿：

```
=IMAGE("https://quickchart.io/qr?text=" & A2 & "&size=250&margin=2")
```

QR Code 內容只有編號本身。前台若掃到完整的 quickchart 網址，也會自動擷取 `text=` 後的編號。

## 4. 後台 API（Code.gs）

網址為 Apps Script 的「網頁應用程式網址」。前台以 HTTP POST 傳送 JSON 內文；為了方便測試，也可以用 GET 帶相同名稱的參數。所有回應都是 JSON，並帶有 `ok` 欄位：

```json
{ "ok": false, "code": "auth", "message": "請先登入" }
```

除了 `login` 以外，所有動作都必須帶登入取得的 `token`。token 無效、過期或帳號被停用時，回應的 `code` 為 `auth`，前台會自動轉到登入頁。

### 4.1 登入

```json
{ "action": "login", "user": "1001", "password": "****" }
```

| 條件 | `ok` | `code` | `message` |
|---|---|---|---|
| 帳號密碼正確且帳號啟用 | `true` | | `登入成功`，並回傳 `token` 與 `user`（`id`、`name`、`role`） |
| 帳號不存在或密碼錯誤 | `false` | `bad_login` | `帳號或密碼錯誤` |
| 密碼正確但狀態欄為不啟用 | `false` | `disabled` | `此帳號目前為「不啟用」，無法登入，請洽管理員` |
| 同一帳號連續錯 5 次 | `false` | `locked` | `登入失敗次數過多，請 10 分鐘後再試` |

登入有效時間為 6 小時，期間每次操作都會重新計時。回應中不會包含密碼。

### 4.2 登出與目前身分

```json
{ "action": "logout", "token": "..." }
{ "action": "me", "token": "..." }
```

`logout` 會讓該 token 立即失效。`me` 回傳目前登入的 `user`。

### 4.3 借用

```json
{ "action": "borrow", "id": "1001", "token": "..." }
```

| 條件 | `ok` | `message` | Sheet 變化 |
|---|---|---|---|
| C 欄為「可借用」 | `true` | `借用成功！\n{廠牌} {名稱}\n借用人：{姓名}\n狀態已更新為：借出中` | C 欄改為「借出中」，紀錄分頁新增一列 |
| C 欄不是「可借用」 | `false` | `借用失敗！該設備目前狀態為：{狀態}` | 無 |
| 編號不存在 | `false` | `找不到設備編號：{id}` | 無 |

`action` 省略時預設為 `borrow`。

### 4.4 歸還

```json
{ "action": "return", "id": "1001", "token": "..." }
```

| 條件 | `ok` | `message` | Sheet 變化 |
|---|---|---|---|
| C 欄為「借出中」 | `true` | `歸還成功！\n{廠牌} {名稱}\n歸還人：{姓名}\n狀態已更新為：可借用` | C 欄改為「可借用」，紀錄分頁新增一列 |
| C 欄不是「借出中」 | `false` | `歸還失敗！該設備目前狀態為：{狀態}（未在借出狀態）` | 無 |
| 編號不存在 | `false` | `找不到設備編號：{id}` | 無 |

任何已登入的使用者都可以歸還，不限原借用人。

### 4.5 設備清單

```json
{ "action": "list", "token": "..." }
```

回應：

```json
{
  "ok": true,
  "updatedAt": "2026/10/30 14:05:30",
  "items": [
    { "id": "1001", "name": "數位相機", "status": "可借用", "brand": "Canon" },
    { "id": "1002", "name": "三腳架",   "status": "借出中", "brand": "Manfrotto" }
  ]
}
```

A 欄空白的列會略過。使用者資料不會出現在回應中。

### 4.6 借還紀錄

```json
{ "action": "log", "limit": 50, "token": "..." }
```

`limit` 省略時為 50，上限 500。回應由新到舊排列：

```json
{
  "ok": true,
  "records": [
    { "time": "2026/10/30 14:05:30", "id": "1004", "name": "投影機",
      "brand": "Epson", "action": "借用", "status": "借出中",
      "userId": "1001", "userName": "陳建宏" }
  ]
}
```

紀錄分頁不存在或沒有資料時回傳 `{ "ok": true, "records": [] }`。

### 4.7 函式一覽

| 函式 | 說明 |
|---|---|
| `doGet(e)`、`doPost(e)` | 進入點。取出參數後交給 `respond`。 |
| `respond(params)` | 呼叫 `handle` 並把結果轉成 JSON；發生例外時回傳 `code: "error"`。 |
| `handle(p)` | 依 `action` 分派。`login`、`logout` 以外的動作先檢查 token。 |
| `getUsers()`、`findUser(id)` | 讀取 `使用者名單`（含密碼，只在後台內部使用）。 |
| `publicUser(u)` | 去掉密碼後可回傳給前台的使用者資料。 |
| `login(user, password)` | 比對帳號密碼、檢查狀態與鎖定，成功時發出 token。 |
| `logout(token)` | 刪除 token。 |
| `getSessionUser(token)` | 由 token 找出登入者，並延長登入時間。 |
| `changeStatus(id, action, user)` | 借用或歸還，更新 C 欄並寫紀錄。 |
| `getEquipmentList()` | 讀取設備欄位，整理成物件陣列。 |
| `getLog(limit)` | 讀取 `借還紀錄` 最後 `limit` 列，反轉成新到舊。 |
| `appendLog(ss, id, name, brand, action, status, user)` | 寫一列紀錄。分頁不存在時建立、寫標題、粗體、凍結第一列。 |
| `jsonOutput(obj)` | 把物件轉成 JSON 回應，並設定 MIME 類型。 |
| `formatTime(d)` | 以專案時區格式化日期。 |

登入狀態存在 Apps Script 的 `CacheService`，不寫入試算表。

### 4.8 常數

| 常數 | 預設值 | 說明 |
|---|---|---|
| `LIST_SHEET_NAME` | `Equipment_List` | 設備清單分頁名稱 |
| `LOG_SHEET_NAME` | `借還紀錄` | 紀錄分頁名稱 |
| `USER_SHEET_NAME` | `使用者名單` | 使用者資料所在的分頁名稱 |
| `USER_START_COL` | `1` | 使用者資料的起始欄，`1` 代表 A 欄 |
| `DISABLED_STATUSES` | `不啟用`、`停用` | 狀態欄出現這些文字時不可登入 |
| `SESSION_SECONDS` | `21600` | 登入有效秒數，上限為 21600（6 小時） |
| `MAX_LOGIN_FAILS` | `5` | 連續輸入錯誤幾次後鎖定 |
| `LOCK_SECONDS` | `600` | 鎖定秒數 |

若分頁改名，改對應的常數即可。使用者的五個欄位必須相鄰，順序固定為編號、姓名、職稱、狀態、密碼；若不是從 A 欄開始，把 `USER_START_COL` 改成起始欄的編號。

## 5. 前台：掃描頁（index.html）

### 5.1 畫面元件

| 元件 | id | 說明 |
|---|---|---|
| 登入者列 | `user-bar` | 顯示登入者姓名與職稱，以及「登出」按鈕 |
| 借用按鈕 | `btn-borrow` | 切換為借用模式，藍色為選取中 |
| 歸還按鈕 | `btn-return` | 切換為歸還模式，綠色為選取中 |
| 模式提示 | `mode-hint` | 顯示目前模式與掃描後的狀態變化 |
| 總覽連結 | （class `status-link`） | 在新分頁開啟 `status.html` |
| 鏡頭選單 | `camera-select` | 列出裝置所有鏡頭，切換後重新啟動掃描 |
| 掃描區 | `reader` | html5-qrcode 的相機畫面 |
| 結果區 | `result` | 顯示處理中、成功（綠）、失敗（紅）訊息 |

### 5.2 流程

1. 頁面載入時檢查登入狀態，未登入就轉到 `login.html`，登入後自動回來。
2. 已登入時向瀏覽器要求鏡頭清單，預設啟動第一個鏡頭。
3. 掃到 QR Code 時，若 `isProcessing` 為 true 則忽略，避免同一張連續觸發多次。
4. 若內容包含 `text=`，擷取其後的編號；去除前後空白。
5. 以 `api({ action: currentMode, id: 編號 })` 呼叫後台，`currentMode` 為 `borrow` 或 `return`，登入 token 會自動帶上。
6. 顯示回應的 `message`。`ok` 為 true 顯示綠色，否則紅色。
7. 3.5 秒後清除訊息並解除 `isProcessing`，可掃下一張。

### 5.3 可調整參數

| 位置 | 預設值 | 說明 |
|---|---|---|
| `config.fps` | 10 | 每秒辨識次數 |
| `config.qrbox` | 250×250 | 掃描框大小 |
| `setTimeout` 延遲 | 3500 毫秒 | 掃描成功後的冷卻時間 |

## 6. 前台：總覽頁（status.html）

### 6.1 畫面元件

| 區塊 | 說明 |
|---|---|
| 登入者列 | 登入者姓名與職稱、「登出」按鈕 |
| 工具列 | 最後更新時間、「立即更新」按鈕、「每 10 秒自動更新」勾選框 |
| 統計卡片 | 設備總數、可借用數（綠）、借出中數（紅） |
| 設備清單 | 搜尋框（編號、名稱、廠牌）、狀態篩選、表格 |
| 最近借還紀錄 | 最近 50 筆，新到舊，借用藍字、歸還綠字，並顯示操作的使用者 |

手機寬度（480px 以下）會隱藏廠牌欄與更新後狀態欄。

### 6.2 流程

1. 頁面載入時檢查登入狀態，未登入就轉到 `login.html`，登入後自動回來。
2. 呼叫 `loadAll()`，同時發出 `list` 與 `log` 兩個請求。
3. 回應後更新統計、清單、紀錄。
4. 若自動更新勾選中，每 10 秒重複一次。
5. 任一請求失敗時，在 `error` 區顯示「讀取資料失敗」，不清除原有畫面。
6. 登入過期或帳號被停用時，清除登入資料並轉到登入頁。

### 6.3 可調整參數

| 位置 | 預設值 | 說明 |
|---|---|---|
| `LOG_LIMIT` | 50 | 顯示的紀錄筆數 |
| `setInterval` 間隔 | 10000 毫秒 | 自動更新間隔 |

## 7. 前台：登入與共用模組（login.html、auth.js）

### 7.1 登入流程

1. 開啟掃描頁或總覽頁時若尚未登入，會轉到 `login.html?next={原本的頁面}`。
2. 輸入使用者編號與密碼後呼叫後台 `login`。
3. 成功時把 `token` 與使用者的編號、姓名、職稱存在瀏覽器的 `localStorage`，再前往原本的頁面。密碼不會被儲存。
4. 失敗時在按鈕下方顯示後台回覆的原因。
5. 同一個瀏覽器的掃描頁與總覽頁共用登入狀態，登入一次即可。

### 7.2 登出

按任一頁上方的「登出」按鈕，會通知後台讓 token 失效、清除瀏覽器裡的登入資料，並回到登入頁。在共用的裝置上使用後請記得登出。

### 7.3 `auth.js` 提供的函式

| 函式 | 說明 |
|---|---|
| `getSession()`、`setSession(s)`、`clearSession()` | 讀取、儲存、清除瀏覽器裡的登入資料 |
| `requireLogin()` | 未登入時轉到登入頁；已登入時回傳登入資料 |
| `api(params, withToken)` | 以 POST 呼叫後台並回傳 JSON。預設自動帶 token；後台回覆 `auth` 時轉到登入頁 |
| `logout()` | 登出 |
| `renderUserBar(el, session)` | 在指定元素顯示登入者與登出按鈕 |

### 7.4 可調整參數

| 位置 | 預設值 | 說明 |
|---|---|---|
| `API_URL` | （GAS 網址） | 後台網址。全站只有 `auth.js` 這一處需要修改 |
| `SESSION_KEY` | `equipment_session` | 登入資料在 `localStorage` 的名稱 |

## 8. 部署摘要

1. **後台**：Google Sheet >「擴充功能」>「Apps Script」，貼上 `Code.gs`，儲存。
2. **發布**：「部署」>「管理部署」> 編輯 > 版本選「新版本」> 部署。只儲存不會生效。存取權須為「所有人」。
3. **檢查網址**：`auth.js` 的 `API_URL` 須與發布的網址一致。一個專案可以有多個部署，每個部署的網址都不同。
4. **前台**：`login.html`、`index.html`、`status.html`、`auth.js` 上傳到 GitHub 專案，開啟 GitHub Pages，等 1 到 3 分鐘。
5. **使用者**：在 `使用者名單` 分頁填入至少一位使用者。
6. **測試**：登入、借用一台、看總覽頁、歸還同一台、確認紀錄分頁有兩列且有使用者姓名、登出。

## 9. 常見問題

| 症狀 | 原因 | 處理 |
|---|---|---|
| 掃描後「系統連線錯誤」 | `API_URL` 錯誤或後台未發布 | 檢查 `auth.js` 的網址，重新發布新版本 |
| 登入頁「系統連線錯誤」 | 後台仍是沒有登入功能的舊版 | 貼上新的 `Code.gs`，發布新版本 |
| 總覽頁「讀取資料失敗」 | 後台仍是舊版 | 發布新版本 |
| 帳號密碼正確卻登入失敗 | 密碼開頭的 `0` 被試算表吃掉，或儲存格前後有多餘字元 | `使用者名單` 的 E 欄格式設為「純文字」後重新輸入密碼 |
| 「登入失敗次數過多」 | 同一帳號連續輸入錯誤 5 次 | 等 10 分鐘再試 |
| 用到一半被要求重新登入 | 超過 6 小時沒有操作，或帳號被改成不啟用 | 重新登入，或請管理員檢查 `使用者名單` 的狀態欄 |
| 改了程式但手機沒變 | 瀏覽器或 GitHub Pages 快取，約 10 分鐘 | 重新整理，或在網址後加 `?v=2` |
| 紀錄時間差 8 小時 | Apps Script 時區 | 左側「專案設定」> 時區「Asia/Taipei」 |
| 相機打不開 | 未授權或非 https | 允許相機權限，確認網址為 https |
| 找不到設備編號 | A 欄值與 QR Code 不一致 | 檢查是否有空白或儲存格被當成數字格式 |

## 10. 已知限制與可擴充方向

- 密碼以明文存在試算表中，能開啟試算表的人都看得到。請只把試算表共用給管理員，並避免使用與其他服務相同的密碼。
- 職稱目前只用於顯示，所有已登入的使用者權限相同。若要限制某些職稱才能借用，可在後台 `handle` 依 `user.role` 判斷。
- 任何已登入的使用者都能歸還別人借的設備。若要限制為原借用人，需在歸還時比對紀錄分頁中該設備最後一筆借用紀錄。
- 沒有修改密碼的畫面，密碼由管理員直接在試算表修改。
- 同一秒內兩人掃同一台設備，理論上可能都成功。可在後台加 `LockService` 避免。
- 總覽頁以輪詢更新，設備數上千時可拉長間隔或改為手動更新。
- 狀態值固定為「可借用」與「借出中」。若需「維修中」等狀態，需同時修改後台判斷與總覽頁的標籤樣式。
