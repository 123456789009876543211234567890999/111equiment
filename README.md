# 設備掃描借用／歸還系統

以手機掃描 QR Code 借用與歸還設備，狀態與紀錄即時寫入 Google Sheet，並提供一個狀態總覽網頁。使用前須以試算表中的帳號密碼登入並輸入圖形驗證碼，每筆借還紀錄都會記下操作人。登入後 5 分鐘沒有操作會自動登出。使用者可以自行建立帳號，經管理員啟用後才能登入。

---

## 1. 系統架構

```
                                ┌──────────────┐  action=login
                 未登入時轉入 ─▶ │ login.html   │ ────────────┐
                                │ 登入頁        │             │
                                └──────────────┘             ▼
┌──────────────┐  掃描 QR Code   ┌──────────────┐  HTTP POST   ┌──────────────────┐
│ 手機瀏覽器    │ ─────────────▶ │ index.html   │ ────────────▶ │ Google Apps      │
│ (GitHub Pages)│                │ 掃描借還頁    │ borrow/return│ Script (Code.gs) │
└──────────────┘                └──────────────┘   + token     └────────┬─────────┘
                                                                        │ 讀寫
┌──────────────┐  每 10 秒輪詢  ┌──────────────┐  HTTP POST             ▼
│ 手機／電腦    │ ─────────────▶ │ status.html  │ ────────────▶ ┌──────────────────┐
│ 瀏覽器        │                │ 狀態總覽頁    │  list / log  │ Google Sheet     │
└──────────────┘                └──────────────┘   + token     │ Equipment_List   │
                                                               │ 使用者名單        │
                                                               │ 借還紀錄          │
                                                               └──────────────────┘
```

| 層級 | 技術 | 部署位置 |
|---|---|---|
| 前台 | HTML + JavaScript + html5-qrcode | GitHub Pages |
| 後台 | Google Apps Script（網頁應用程式） | Google 雲端 |
| 資料庫 | Google Sheet | Google 雲端 |
| QR Code | quickchart.io 免費 API，由 Sheet 公式產生 | Google Sheet 儲存格 |

## 2. 檔案說明

| 檔案 | 用途 |
|---|---|
| `login.html` | 登入頁。輸入使用者編號、密碼與圖形驗證碼，成功後進入掃描頁或總覽頁。 |
| `register.html` | 建立帳號頁。填寫帳號、姓名、密碼與圖形驗證碼，建立後狀態為「待審核」。 |

| `Code.gs` | 後台。產生驗證碼、驗證登入、建立帳號、接收前台請求，讀寫 Google Sheet。 |

## 3. Google Sheet 結構

### 3.1 `Equipment_List` 分頁（設備，需手動建立）

第一列為標題列，程式從第二列開始讀取。

| 欄 | 欄名 | 說明 |
|---|---|---|
| A | 設備編號 | 唯一值，建議 4 碼數字，例如 `1001`。QR Code 內容即為此值。 |
| B | 名稱 | 例如 `數位相機` |
| C | 狀態 | 只能是 `可借用` 或 `借出中`，由程式自動更新 |
| D | QR Code | 公式產生，見 3.4。程式不讀取 |
| E | 廠牌 | 例如 `Canon` |

### 3.2 `使用者名單` 分頁（使用者，需手動建立）

第一列為標題列，程式從第二列開始讀取。

| 欄 | 欄名 | 說明 |
|---|---|---|
| A | 使用者編號 | 登入帳號，唯一值，例如 `1001` |
| B | 姓名 | 登入後顯示在畫面上，並寫入借還紀錄 |
| C | 職稱 | 例如 `teacher`，登入後顯示在姓名旁 |
| D | 狀態 | 空白代表啟用。填 `不啟用`、`停用` 或 `待審核` 時該帳號無法登入 |
| E | 密碼 | 登入密碼。空白的帳號無法登入 |

管理員新增使用者只要往下加一列，不需要重新部署。使用者也可以從登入頁的「建立帳號」自行申請，程式會在最後新增一列，狀態為 `待審核`；管理員確認後把該列的狀態清空，帳號就能登入。不想核准就把整列刪掉。
把狀態改成 `不啟用` 後，該使用者已登入的裝置在下一次操作時也會被登出。

密碼若以 `0` 開頭（例如 `0000`），請先把 E 欄的格式設為「純文字」再輸入，否則試算表會把它存成數字 `0`。

### 3.3 `借還紀錄` 分頁（程式自動建立）

第一次借用或歸還成功時自動建立，不需手動新增。

| 欄 | 欄名 | 說明 |
|---|---|---|
| A | 時間 | 格式 `yyyy/MM/dd HH:mm:ss` |
| B | 設備編號 | |
| C | 名稱 | |
| D | 廠牌 | |
| E | 動作 | `借用` 或 `歸還` |
| F | 更新後狀態 | `借出中` 或 `可借用` |
| G | 使用者編號 | 操作人的編號 |
| H | 使用者 | 操作人的姓名 |

加入登入功能前建立的紀錄分頁只有 A 到 F 欄。下一次借還時程式會自動補上 G、H 的標題，舊紀錄的這兩欄留空。

### 3.4 QR Code 產生公式

在 `Equipment_List` 的 D2 輸入後往下填滿：

```
=IMAGE("https://quickchart.io/qr?text=" & A2 & "&size=250&margin=2")
```

QR Code 內容只有編號本身。前台若掃到完整的 quickchart 網址，也會自動擷取 `text=` 後的編號。

## 4. 後台 API（Code.gs）

網址為 Apps Script 的「網頁應用程式網址」。前台以 HTTP POST 傳送 JSON 內文；為了方便測試，也可以用 GET 帶相同名稱的參數。所有回應都是 JSON，並帶有 `ok` 欄位：

```json
{ "ok": false, "code": "auth", "message": "請先登入" }
```

除了 `captcha`、`login`、`register` 以外，所有動作都必須帶登入取得的 `token`。token 無效、過期或帳號被停用時，回應的 `code` 為 `auth`，前台會自動轉到登入頁。

### 4.1 圖形驗證碼

```json
{ "action": "captcha" }
```

回應：

```json
{ "ok": true, "id": "3f2a…", "svg": "<svg …>…</svg>" }
```

後台隨機產生 4 位數字，把答案存在快取 5 分鐘，只回傳編號 `id` 與一張 SVG 圖片。圖片中的數字是用線條畫出來的，不含文字，每個數字的位置、大小、角度都隨機偏移，並加上干擾線與雜點。答案不會傳給前台。

每組驗證碼只能用一次，不論輸入對錯都會作廢，所以每次登入失敗後前台都會換一張新的。

### 4.2 登入

```json
{ "action": "login", "user": "1001", "password": "****", "captchaId": "3f2a…", "captcha": "1234" }
```

後台先檢查驗證碼，通過後才比對密碼。

| 條件 | `ok` | `code` | `message` |
|---|---|---|---|
| 驗證碼錯誤、過期或已用過 | `false` | `bad_captcha` | `驗證碼錯誤或已過期，請重新輸入` |
| 帳號密碼正確且帳號啟用 | `true` | | `登入成功`，並回傳 `token` 與 `user`（`id`、`name`、`role`） |
| 帳號不存在或密碼錯誤 | `false` | `bad_login` | `帳號或密碼錯誤` |
| 密碼正確但狀態欄為不啟用 | `false` | `disabled` | `此帳號目前為「不啟用」，無法登入，請洽管理員` |
| 同一帳號連續錯 5 次 | `false` | `locked` | `登入失敗次數過多，請 10 分鐘後再試` |

驗證碼錯誤不會計入帳號的錯誤次數。回應中不會包含密碼。

### 4.3 建立帳號

```json
{ "action": "register", "user": "newt01", "name": "林老師", "password": "****", "captchaId": "3f2a…", "captcha": "1234" }
```

不需要登入，但需要驗證碼。成功時在 `使用者名單` 最後新增一列：職稱為 `NEW_USER_ROLE`，狀態為 `NEW_USER_STATUS`（預設 `待審核`）。

| 條件 | `ok` | `code` | `message` |
|---|---|---|---|
| 建立成功 | `true` | | `帳號已建立，目前狀態為「待審核」。請等管理員啟用後再登入。`，並帶 `pending: true` |
| 驗證碼錯誤、過期或已用過 | `false` | `bad_captcha` | `驗證碼錯誤或已過期，請重新輸入` |
| 帳號不是 4 到 20 個英文字母或數字 | `false` | `bad_id` | `帳號須為 4 到 20 個英文字母或數字` |
| 姓名超過 20 字、含 `< >`，或以 `= + - @ '` 開頭 | `false` | `bad_name` | 說明規則 |
| 密碼少於 4 或多於 50 字元、前後有空白，或以 `= + - @ '` 開頭 | `false` | `bad_password` | 說明規則 |
| 帳號已存在（不分大小寫） | `false` | `exists` | `此帳號已被使用，請換一個` |
| 一小時內已建立 20 個帳號 | `false` | `busy` | `目前建立帳號的人數過多，請稍後再試` |

不接受以 `= + - @ '` 開頭的姓名與密碼，是因為這類文字寫進試算表可能被當成公式執行。寫入前會先把該列設成純文字格式，`0123` 這類帳號或密碼才不會被存成數字。檢查與寫入在 `LockService` 鎖定下進行，兩個人同時申請同一個帳號時只有一個會成功。

### 4.4 登出、目前身分與延長登入

```json
{ "action": "logout", "token": "..." }
{ "action": "me", "token": "..." }
{ "action": "ping", "token": "..." }
```

`logout` 會讓該 token 立即失效。`me` 回傳目前登入的 `user`。`ping` 只用來告訴後台「使用者還在操作」。

token 在 6 分鐘沒有操作後失效。會重新計時的動作是 `login`、`ping`、`me`、`borrow`、`return`。`list` 與 `log` 不會重新計時，因為總覽頁每 10 秒會自動呼叫它們，那不代表有人在操作。前台的閒置上限是 5 分鐘，後台多留 1 分鐘緩衝。

### 4.5 借用

```json
{ "action": "borrow", "id": "1001", "token": "..." }
```

| 條件 | `ok` | `message` | Sheet 變化 |
|---|---|---|---|
| C 欄為「可借用」 | `true` | `借用成功！\n{廠牌} {名稱}\n借用人：{姓名}\n狀態已更新為：借出中` | C 欄改為「借出中」，紀錄分頁新增一列 |
| C 欄不是「可借用」 | `false` | `借用失敗！該設備目前狀態為：{狀態}` | 無 |
| 編號不存在 | `false` | `找不到設備編號：{id}` | 無 |

`action` 省略時預設為 `borrow`。

### 4.6 歸還

```json
{ "action": "return", "id": "1001", "token": "..." }
```

| 條件 | `ok` | `message` | Sheet 變化 |
|---|---|---|---|
| C 欄為「借出中」 | `true` | `歸還成功！\n{廠牌} {名稱}\n歸還人：{姓名}\n狀態已更新為：可借用` | C 欄改為「可借用」，紀錄分頁新增一列 |
| C 欄不是「借出中」 | `false` | `歸還失敗！該設備目前狀態為：{狀態}（未在借出狀態）` | 無 |
| 編號不存在 | `false` | `找不到設備編號：{id}` | 無 |

任何已登入的使用者都可以歸還，不限原借用人。

### 4.7 設備清單

```json
{ "action": "list", "token": "..." }
```

回應：

```json
{
  "ok": true,
  "updatedAt": "2026/10/30 14:05:30",
  "items": [
    { "id": "1001", "name": "數位相機", "status": "可借用", "brand": "Canon" },
    { "id": "1002", "name": "三腳架",   "status": "借出中", "brand": "Manfrotto" }
  ]
}
```

A 欄空白的列會略過。使用者資料不會出現在回應中。

### 4.8 借還紀錄

```json
{ "action": "log", "limit": 50, "token": "..." }
```

`limit` 省略時為 50，上限 500。回應由新到舊排列：

```json
{
  "ok": true,
  "records": [
    { "time": "2026/10/30 14:05:30", "id": "1004", "name": "投影機",
      "brand": "Epson", "action": "借用", "status": "借出中",
      "userId": "1001", "userName": "陳建宏" }
  ]
}
```

紀錄分頁不存在或沒有資料時回傳 `{ "ok": true, "records": [] }`。

### 4.9 函式一覽

| 函式 | 說明 |
|---|---|
| `doGet(e)`、`doPost(e)` | 進入點。取出參數後交給 `respond`。 |
| `respond(params)` | 呼叫 `handle` 並把結果轉成 JSON；發生例外時回傳 `code: "error"`。 |
| `handle(p)` | 依 `action` 分派。`captcha`、`login`、`register`、`logout` 以外的動作先檢查 token。 |
| `createCaptcha()` | 產生驗證碼，答案存入快取，回傳編號與圖片。 |
| `checkCaptcha(id, answer)` | 比對驗證碼並作廢。 |
| `drawCaptcha(code)` | 把數字畫成 SVG 圖片。 |
| `getUsers()`、`findUser(id)` | 讀取 `使用者名單`（含密碼，只在後台內部使用）。 |
| `publicUser(u)` | 去掉密碼後可回傳給前台的使用者資料。 |
| `login(user, password, captchaId, captcha)` | 檢查驗證碼、比對帳號密碼、檢查狀態與鎖定，成功時發出 token。 |
| `register(user, name, password, captchaId, captcha)` | 檢查驗證碼與各欄位後，在 `使用者名單` 新增一列。 |
| `looksLikeFormula(text)` | 判斷文字是否以 `= + - @ '` 開頭。 |
| `logout(token)` | 刪除 token。 |
| `getSessionUser(token, renew)` | 由 token 找出登入者。`renew` 為 true 時重新計算有效時間。 |
| `changeStatus(id, action, user)` | 借用或歸還，更新 C 欄並寫紀錄。 |
| `getEquipmentList()` | 讀取設備欄位，整理成物件陣列。 |
| `getLog(limit)` | 讀取 `借還紀錄` 最後 `limit` 列，反轉成新到舊。 |
| `appendLog(ss, id, name, brand, action, status, user)` | 寫一列紀錄。分頁不存在時建立、寫標題、粗體、凍結第一列。 |
| `jsonOutput(obj)` | 把物件轉成 JSON 回應，並設定 MIME 類型。 |
| `formatTime(d)` | 以專案時區格式化日期。 |

登入狀態與驗證碼答案存在 Apps Script 的 `CacheService`，不寫入試算表。

### 4.10 常數

| 常數 | 預設值 | 說明 |
|---|---|---|
| `LIST_SHEET_NAME` | `Equipment_List` | 設備清單分頁名稱 |
| `LOG_SHEET_NAME` | `借還紀錄` | 紀錄分頁名稱 |
| `USER_SHEET_NAME` | `使用者名單` | 使用者資料所在的分頁名稱 |
| `USER_START_COL` | `1` | 使用者資料的起始欄，`1` 代表 A 欄 |
| `DISABLED_STATUSES` | `不啟用`、`停用`、`待審核` | 狀態欄出現這些文字時不可登入 |
| `NEW_USER_STATUS` | `待審核` | 自行建立的帳號寫入的狀態。改成 `""` 則建立後立刻可以登入，任何人都能自行取得帳號，請斟酌 |
| `NEW_USER_ROLE` | `teacher` | 自行建立的帳號寫入的職稱，管理員可在試算表修改 |
| `MAX_REGISTER_PER_HOUR` | `20` | 一小時內最多可建立幾個帳號 |
| `SESSION_SECONDS` | `360` | 沒有操作多久後 token 失效（秒）。應比前台的 `IDLE_MINUTES` 多約 1 分鐘 |
| `CAPTCHA_SECONDS` | `300` | 驗證碼有效秒數 |
| `CAPTCHA_LENGTH` | `4` | 驗證碼位數。修改時登入頁輸入框的 `maxlength` 與說明文字也要跟著改 |
| `MAX_LOGIN_FAILS` | `5` | 連續輸入錯誤幾次後鎖定 |
| `LOCK_SECONDS` | `600` | 鎖定秒數 |

若分頁改名，改對應的常數即可。使用者的五個欄位必須相鄰，順序固定為編號、姓名、職稱、狀態、密碼；若不是從 A 欄開始，把 `USER_START_COL` 改成起始欄的編號。

## 5. 前台：掃描頁（index.html）

### 5.1 畫面元件

| 元件 | id | 說明 |
|---|---|---|
| 登入者列 | `user-bar` | 顯示登入者姓名與職稱，以及「登出」按鈕 |
| 借用按鈕 | `btn-borrow` | 切換為借用模式，藍色為選取中 |
| 歸還按鈕 | `btn-return` | 切換為歸還模式，綠色為選取中 |
| 模式提示 | `mode-hint` | 顯示目前模式與掃描後的狀態變化 |
| 總覽連結 | （class `status-link`） | 在新分頁開啟 `status.html` |
| 鏡頭選單 | `camera-select` | 列出裝置所有鏡頭，切換後重新啟動掃描 |
| 掃描區 | `reader` | html5-qrcode 的相機畫面 |
| 結果區 | `result` | 顯示處理中、成功（綠）、失敗（紅）訊息 |

### 5.2 流程

1. 頁面載入時檢查登入狀態，未登入就轉到 `login.html`，登入後自動回來。
2. 已登入時向瀏覽器要求鏡頭清單，預設啟動第一個鏡頭。
3. 掃到 QR Code 時，若 `isProcessing` 為 true 則忽略，避免同一張連續觸發多次。
4. 若內容包含 `text=`，擷取其後的編號；去除前後空白。
5. 以 `api({ action: currentMode, id: 編號 })` 呼叫後台，`currentMode` 為 `borrow` 或 `return`，登入 token 會自動帶上。
6. 顯示回應的 `message`。`ok` 為 true 顯示綠色，否則紅色。
7. 3.5 秒後清除訊息並解除 `isProcessing`，可掃下一張。

### 5.3 可調整參數

| 位置 | 預設值 | 說明 |
|---|---|---|
| `config.fps` | 10 | 每秒辨識次數 |
| `config.qrbox` | 250×250 | 掃描框大小 |
| `setTimeout` 延遲 | 3500 毫秒 | 掃描成功後的冷卻時間 |

## 6. 前台：總覽頁（status.html）

### 6.1 畫面元件

| 區塊 | 說明 |
|---|---|
| 登入者列 | 登入者姓名與職稱、「登出」按鈕 |
| 工具列 | 最後更新時間、「立即更新」按鈕、「每 10 秒自動更新」勾選框 |
| 統計卡片 | 設備總數、可借用數（綠）、借出中數（紅） |
| 設備清單 | 搜尋框（編號、名稱、廠牌）、狀態篩選、表格 |
| 最近借還紀錄 | 最近 50 筆，新到舊，借用藍字、歸還綠字，並顯示操作的使用者 |

手機寬度（480px 以下）會隱藏廠牌欄與更新後狀態欄。

### 6.2 流程

1. 頁面載入時檢查登入狀態，未登入就轉到 `login.html`，登入後自動回來。
2. 呼叫 `loadAll()`，同時發出 `list` 與 `log` 兩個請求。
3. 回應後更新統計、清單、紀錄。
4. 若自動更新勾選中，每 10 秒重複一次。
5. 任一請求失敗時，在 `error` 區顯示「讀取資料失敗」，不清除原有畫面。
6. 登入過期或帳號被停用時，清除登入資料並轉到登入頁。

### 6.3 可調整參數

| 位置 | 預設值 | 說明 |
|---|---|---|
| `LOG_LIMIT` | 50 | 顯示的紀錄筆數 |
| `setInterval` 間隔 | 10000 毫秒 | 自動更新間隔 |

## 7. 前台：登入、建立帳號與共用模組（login.html、register.html、auth.js）

### 7.1 登入流程

1. 開啟掃描頁或總覽頁時若尚未登入，會轉到 `login.html?next={原本的頁面}`。
2. 登入頁載入時向後台要一張驗證碼圖片。看不清楚可以按「換一張」。
3. 輸入使用者編號、密碼與圖片中的 4 個數字後呼叫後台 `login`。
4. 成功時把 `token` 與使用者的編號、姓名、職稱存在瀏覽器的 `localStorage`，再前往原本的頁面。密碼不會被儲存。
5. 失敗時在按鈕下方顯示後台回覆的原因，並自動換一張新的驗證碼。
6. 同一個瀏覽器的掃描頁與總覽頁共用登入狀態，登入一次即可。

### 7.2 登出

按任一頁上方的「登出」按鈕，會通知後台讓 token 失效、清除瀏覽器裡的登入資料，並回到登入頁。在共用的裝置上使用後請記得登出。

### 7.3 建立帳號

1. 在登入頁按「建立帳號」進入 `register.html`。
2. 填寫帳號、姓名、密碼（輸入兩次）與驗證碼。
3. 瀏覽器先檢查格式與兩次密碼是否一致，再呼叫後台 `register`。
4. 成功後畫面顯示「帳號已建立，目前狀態為待審核」。建立帳號不會自動登入。
5. 管理員打開 `使用者名單` 分頁，確認是認識的人後把該列的狀態欄清空，必要時修改職稱。之後這個帳號就能登入。
6. 若 `NEW_USER_STATUS` 設為 `""`，則跳過審核，建立後直接回到登入頁。

### 7.4 閒置自動登出

登入後若 5 分鐘沒有操作，會自動登出並回到登入頁，登入頁上方會顯示原因。

- **算操作的動作**：點擊、觸控、按鍵、開啟頁面、掃描成功。
- **不算操作的動作**：總覽頁每 10 秒的自動更新、相機畫面持續開著。
- 掃描頁與總覽頁共用同一個計時，在其中一頁操作，另一頁也不會被登出。
- 手機鎖定或把瀏覽器切到背景時計時仍然繼續，回來時若已超過 5 分鐘會立刻登出。
- 前台每 5 秒檢查一次，所以實際登出時間最多晚 5 秒。
- 有操作時前台最多每 30 秒呼叫一次後台的 `ping`，讓後台的 token 跟著延長。即使有人繞過前台，token 在後台也會於 6 分鐘無操作後失效。

### 7.5 `auth.js` 提供的函式

| 函式 | 說明 |
|---|---|
| `getSession()`、`setSession(s)`、`clearSession()` | 讀取、儲存、清除瀏覽器裡的登入資料 |
| `requireLogin()` | 未登入或已閒置過久時轉到登入頁；已登入時回傳登入資料並開始監看閒置時間 |
| `markActive()` | 記錄使用者剛剛有操作，重新計算閒置時間 |
| `api(params, withToken)` | 以 POST 呼叫後台並回傳 JSON。預設自動帶 token；後台回覆 `auth` 時轉到登入頁 |
| `createCaptchaBox(img, input, refreshBtn, showError)` | 驗證碼元件，登入頁與建立帳號頁共用 |
| `logout()` | 登出 |
| `renderUserBar(el, session)` | 在指定元素顯示登入者與登出按鈕 |

### 7.6 可調整參數

| 位置 | 預設值 | 說明 |
|---|---|---|
| `IDLE_MINUTES` | 5 | 沒有操作幾分鐘後自動登出。修改時後台的 `SESSION_SECONDS` 要改成這個值的秒數再加 60 |
| `API_URL` | （GAS 網址） | 後台網址。全站只有 `auth.js` 這一處需要修改 |
| `SESSION_KEY` | `equipment_session` | 登入資料在 `localStorage` 的名稱 |

## 8. 部署摘要

1. **後台**：Google Sheet >「擴充功能」>「Apps Script」，貼上 `Code.gs`，儲存。
2. **發布**：「部署」>「管理部署」> 編輯 > 版本選「新版本」> 部署。只儲存不會生效。存取權須為「所有人」。
3. **檢查網址**：`auth.js` 的 `API_URL` 須與發布的網址一致。一個專案可以有多個部署，每個部署的網址都不同。
4. **前台**：`login.html`、`register.html`、`index.html`、`status.html`、`auth.js` 上傳到 GitHub 專案，開啟 GitHub Pages，等 1 到 3 分鐘。
5. **使用者**：在 `使用者名單` 分頁填入至少一位使用者。
6. **測試**：輸入驗證碼登入、借用一台、看總覽頁、歸還同一台、確認紀錄分頁有兩列且有使用者姓名、登出。

## 9. 常見問題

| 症狀 | 原因 | 處理 |
|---|---|---|
| 掃描後「系統連線錯誤」 | `API_URL` 錯誤或後台未發布 | 檢查 `auth.js` 的網址，重新發布新版本 |
| 登入頁「系統連線錯誤」 | 後台仍是沒有登入功能的舊版 | 貼上新的 `Code.gs`，發布新版本 |
| 總覽頁「讀取資料失敗」 | 後台仍是舊版 | 發布新版本 |
| 帳號密碼正確卻登入失敗 | 密碼開頭的 `0` 被試算表吃掉，或儲存格前後有多餘字元 | `使用者名單` 的 E 欄格式設為「純文字」後重新輸入密碼 |
| 建立帳號後無法登入，顯示「待審核」 | 新帳號要管理員啟用 | 管理員到 `使用者名單` 把該列的狀態欄清空 |
| 建立帳號時顯示「此帳號已被使用」 | 帳號重複，大小寫不同也算重複 | 換一個帳號 |
| 「登入失敗次數過多」 | 同一帳號連續輸入錯誤 5 次 | 等 10 分鐘再試 |
| 用到一半被要求重新登入 | 超過 5 分鐘沒有操作，或帳號被改成不啟用 | 重新登入，或請管理員檢查 `使用者名單` 的狀態欄 |
| 登入頁沒有出現驗證碼圖片 | 後台仍是沒有驗證碼功能的舊版，或連線失敗 | 按「換一張」；仍然沒有就重新發布後台新版本 |
| 驗證碼明明輸入正確卻說錯誤 | 驗證碼超過 5 分鐘已過期，或已經用過一次 | 按「換一張」後重新輸入 |
| 登入時瀏覽器警告密碼已外洩 | 密碼太常見（例如 `0000`），這是瀏覽器的提醒，不是系統錯誤 | 在 `使用者名單` 換成不常見的密碼 |
| 改了程式但手機沒變 | 瀏覽器或 GitHub Pages 快取，約 10 分鐘 | 重新整理，或在網址後加 `?v=2` |
| 紀錄時間差 8 小時 | Apps Script 時區 | 左側「專案設定」> 時區「Asia/Taipei」 |
| 相機打不開 | 未授權或非 https | 允許相機權限，確認網址為 https |
| 找不到設備編號 | A 欄值與 QR Code 不一致 | 檢查是否有空白或儲存格被當成數字格式 |

## 10. 已知限制與可擴充方向

- 圖形驗證碼是自製的，能擋住簡單的自動猜密碼程式，但擋不住專門寫來辨識它的程式，也擋不住用人工去猜。真正的防線仍是密碼強度與連錯 5 次鎖定。
- 密碼以明文存在試算表中，能開啟試算表的人都看得到。請只把試算表共用給管理員，並避免使用與其他服務相同的密碼。
- 職稱目前只用於顯示，所有已登入的使用者權限相同。若要限制某些職稱才能借用，可在後台 `handle` 依 `user.role` 判斷。
- 任何已登入的使用者都能歸還別人借的設備。若要限制為原借用人，需在歸還時比對紀錄分頁中該設備最後一筆借用紀錄。
- 沒有修改密碼的畫面，密碼由管理員直接在試算表修改。
- 建立帳號不驗證 Email 或身分，任何知道網址的人都能送出申請，所以預設要管理員審核。申請多時試算表會累積待審核的列，需要管理員定期清理。
- 同一秒內兩人掃同一台設備，理論上可能都成功。可在後台加 `LockService` 避免。
- 總覽頁以輪詢更新，設備數上千時可拉長間隔或改為手動更新。
- 狀態值固定為「可借用」與「借出中」。若需「維修中」等狀態，需同時修改後台判斷與總覽頁的標籤樣式。
